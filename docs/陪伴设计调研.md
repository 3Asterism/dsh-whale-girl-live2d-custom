# 陪伴设计调研：成熟的养成 / 陪伴产品怎么留住人，我们对照了什么

> 2026-10 做 0.6.8 之前查的。目的只有一个：别靠「更多聊天」堆功能，而是照成熟产品验证过的路子，补我们的缺口。
> 结论落地在 `behavior/dev.js`（开发动作钩子 / 今日小账 / 每日一签）和 `persona/devhooks.js`、`persona/fortune.js`。

## 2. 对照：我们已有的 / 缺的

| 成熟产品验证过的做法 | 我们已有 | 这一版补上 |
|---|---|---|
| 个性化 + 投入感 | 44 个表情、装饰、场景、羁绊 10 级、「肥鱼」反差人设 | — |
| 积累的历史 / 资产 | 回忆册（共同经历）、表情包图鉴（157 张）、每周回顾 | **今日小账**：把「今天一起做了什么」沉淀下来（只有次数） |
| 一起做事 > 聊天 | 她跟着 agent 的真实状态动；今日心愿 | **复合故事**：看得懂提交 / push / 测试 / 装依赖，并真的知道成败；一轮结束时合成「红了好几次终于绿了」「改→测→提交」顶替收工那句 |
| 看出你在烦、先承接情绪 | 关键词（累 / 烦 / 骂她）、「站在主人这边」的失败安慰 | **挫败度**：口气 / 重复发同一句 / 反复重新生成 / 测试连红叠加，任务边界轻轻安慰；高风险走温柔分支 |

| 惊喜与收集 | 图鉴、稀有表情包（好感放出） | 签里的**幸运图优先挑图鉴里还没收的**：她丢给你，顺手就收进了图鉴 |
| 她在你不在时也活着 | 离线小事件（离开 >2 小时回来讲一件） | （已有） |
| 用户可控 | 话痨度、各项互动开关、一键重置 | 新增「开发动作反应」「每日一签」两个开关 |
| 不带罪恶感 | 不扣分、不补做、没有连续打卡惩罚、饿了不惩罚 | 签永远是安慰口吻（「凶」= 小虫子比较多，不是主人倒霉）；同一天同一支，没有赌博感 |

**有意不做的**：「宠物受苦」的内疚机制、连续打卡惩罚、情感依赖诱导。调研里这几条是留存的捷径，也是操纵的捷径——她是陪你加班的同事，不是需要你照顾才不会死的电子鸡。

## 3. 落地时守的几条

- **诚实**：成败来自宿主从结果里抽出的退出码（DSH 的 bash / pwsh 非零退出码不算 error，只在结果末尾写 `[exit code: N]`；只转数字、不转输出）。没有退出码（老宿主 / 后台命令 / 被信号杀掉）就既不说成功也不说失败；失败不庆祝。
- **隐私**：命令只在本地用正则分类，只留类别名和计数；主人的话只在内存里留最近 3 句的二元组指纹（10 分钟）；今日小账只有次数；都不上传、不落盘原文。
- **不打扰**：中途不说话，复合故事在一轮结束时**顶替**收工那句；轻话和安慰排队过闸（打字 / 刚互动 / 有提问 / 番茄钟专注都让路），90 秒一次、每小时有上限；抽签的邀请要点按钮才抽、一天只问一次、深夜不问。详见第 4 节。
- **可控**：设置页「互动开关」里两个新开关；说「抽签 / 运势」才会当场抽。

## 4. 「看得懂你在干什么」：信号清单与编排（0.6.8 第二轮）

> 调研补充：[Developer Interaction Patterns with Proactive AI（五天田野研究）](https://arxiv.org/html/2601.10253v1)、
> [Theory of Troubleshooting](https://arxiv.org/pdf/2602.10540)、[Assistance or Disruption?](https://arxiv.org/html/2502.18658v4)、
> [Edit-Run 行为研究](https://arxiv.org/pdf/2109.02682)。

**结论**：① 搭话挑**任务边界**（commit 之后接受率 52%；写到一半插话 62% 被关掉）；② 挫败是**一串信号叠出来的**（反复重试、同一件事绕圈、红了又红），
单个词覆盖不了；③ 复合操作（改→测→提交；红→红→绿）比单条命令有信息量；④ 情绪强度要和事情严重程度匹配，高风险走安全流程而不是继续玩梗。

### 信号清单——只用真的 hook 得到的（已对照 DSH 0.2.0-rc.2 源码核实）

| 信号 | 来源 | 备注 |
|---|---|---|
| shell 命令的类别 | `tool/call` 的参数（bash / pwsh：`command` 字段） | 本地正则；只留类别名，不留命令 |
| 命令成败 | `tool/result` 末尾的 `[exit code: N]` → 宿主抽成 `exit` | **非零退出码不算 error**；超时 / 信号 / 后台 / 沙箱拦截另有标记；只转数字 |
| 改了几个文件 | 写文件类工具的 `tool/call` 次数 | |
| 工具基础设施失败 | `tool/result` 的 `isError` | 起不来进程 / 被中止，不是命令失败 |
| 一轮怎么收场 | `turn/end` 的 `reason.kind`（completed / error / aborted / max-tokens） | |
| 重试 / 提议被拒 | `llm/retry`、`approval/decided` | |
| 主人的口气 / 重复 | `user/message` 的文本 | 本地正则 + 二元组指纹（内存 10 分钟，不留原文） |
| 重新生成 / 停止 / 新建会话 | DOM 点击（只读捕获） | |
| 正在打字 / 番茄钟专注 / 有提问等着 | 输入框事件、番茄钟状态、气泡状态 | 用来「让路」 |

踩到的坑：宿主一直把调用 id 读成 `message.content[0].toolCallId`，而 DSH 自己读 `message.toolCallId`——真实 DSH 里 tool-result 因此没有工具名和耗时（已修）。
**不要信测试夹具**：夹具是照代码写的，核实要回 DSH 源码（见项目记忆里的 asar 读法）。

### 编排：观察者不挤占正常互动
「观察者」= 她自己看出来想说的话（复合故事的轻话、安慰、重来提醒）；「正常互动」= 戳 / 摸 / 关键词 / 点界面 / 报错 / 批准 / 收工。规则（`persona/orchestra.js`，纯函数，`test-empathy` 逐条测）：

1. 中途不说，只记账；任务边界（一轮结束）才可能说；
2. 复合故事的 `flavor` **顶替**默认收工那句（不增加发言）；`note` 和安慰只能排队：一次只留一条（价值更高才替换），会过期、不补播；
3. 过闸：安静档、主人在打字（5s）、刚互动（12s）、有提问 / 批准 / 危险命令、番茄钟专注、气泡被占、她在演别的、面板开着；
4. 配额：两次发言隔 90s，每小时 6（话痨档 12）；
5. 只用 CUE 级：任何正常互动都能顶掉它，它顶不掉别人；
6. 唯一例外：高风险关心，不受配额限制，只避开「正等你点按钮」。

## 5. 还没做 / 下一步想法（调研里有、这一版没碰）

- **记忆透明页**：「她记得什么」——列出羁绊计数、回忆、今日小账，并提供「暂停 / 清除」。现在只有总开关和一键重置。
- **稀有访客**（猫咪后院）：极低概率的小惊喜（比如偶尔有只小鲸来串门）。
- **衣橱 / 资产沉淀**：解锁装饰作为羁绊奖励，让积累的东西看得见。
- 今日小账目前只存本机（localStorage），没进宿主的羁绊存档，所以换浏览器不会带走。

## 6. vibe coding 的经典流程与经典翻车（0.6.8 第三轮）

> 来源：[Why Your Vibe-Coded App Keeps Breaking Every Time You Fix Something](https://dev.to/anatolysilko/why-your-vibe-coded-app-keeps-breaking-every-time-you-fix-something-48p0)、
> [Vibe Coding Is Fine. Vibe Debugging Is What Kills You](https://dev.to/ji_ai/vibe-coding-is-fine-vibe-debugging-is-what-kills-you-23i0)、
> [Context Rot in AI Coding Agents](https://www.mindstudio.ai/blog/context-rot-ai-coding-agents-how-to-prevent)、
> [Checkpoint Commit Patterns](https://understandingdata.com/posts/checkpoint-commit-patterns/)、
> [Why AI Coding Agents Fail: The 9 Failure Modes](https://beginnersinai.org/why-ai-coding-agents-fail/)、
> [9 vibe coding best practices](https://www.softr.io/blog/vibe-coding-best-practices)、[Vibe Coding 最佳实践（中文）](https://github.com/tradecatlabs/vibe-coding-cn/wiki/Vibe-Coding-%E6%9C%80%E4%BD%B3%E5%AE%9E%E8%B7%B5)。

**经典流程**：探索 → **计划**（spec / plan 模式 + 清单）→ **小步实现** → 测试 → 看 diff → **提交当存档点**（每次稳定就 commit，随时能回到已知良好状态）→ 上下文长了**压缩或换新会话**（每 30–45 分钟或一个里程碑；先写 3–5 句现状再清空）。

**经典翻车 → 我们怎么 hook**（全部只用 DSH 真能给到的信号；复合判断都在一轮结束时、过编排器的闸，中途不说话）：

| 经典翻车 | 现象 | 信号（hook） | 她的反应 |
|---|---|---|---|
| 改一个 bug 出三个 | 修好一处，别处又坏；绿了又红 | 上一轮最后一次测试绿、这一轮（或先绿后红）变红（退出码） | 「刚才还是绿的，这次改完变红了…上一处改动嫌疑最大」（regression，同时给挫败度 +10） |
| 原地打转（debug hell） | 同一个报错反复修；AI 盯着同一段失败代码 | 同一条命令（指纹，端口 / 行号不算）失败 ≥3 次；同一个文件（路径哈希）被改 ≥5 次 | 「同一条命令跑了好几遍都没过，换个思路？」/「反复改一处，往往是方向不对」，并给挫败度（loop） |
| 过早宣布完成 | 改了一堆，从没跑过，用户一试就坏 | 改了 ≥3 个文件、整轮没跑测试；主人接着抱怨「还是不行」 | 最对症的一句：「上一轮改完没跑测试，先让它跑一遍？」 |
| 上下文腐烂 | 会话越聊越长，AI 越来越糊涂 | 压缩上下文 ≥2 次（60 分钟内）/ 会话聊了 ≥25 轮 | 「这个会话聊得很长了，新开一个更清爽；换之前先用三五句写下现状」（45 分钟最多一次；新建会话后清零） |
| 没有存档点 | 大改之后一直没提交，坏了回不去 | 绿了、改了 ≥3 个文件、今天一次提交都没有 | 「绿了，要不要先提交存个档？」；已经提交过就只夸「改完就测」 |
| 慌了就回滚 | reset --hard / checkout -- . | 回滚命令退出码 0 | 收工那句换成「回滚不丢人，稳住了再来」（顶替，不增加发言）；失败不说 |
| 幻觉依赖 | AI 编了个不存在的包，装不上 | install 失败且这一轮没装成过 | 「装不上…包名会不会是编出来的？先查查真的存在」 |
| 密钥进仓库 | `git add .env` 一路推上去 | 命令里 `git add` 带 .env / 私钥 / .pem / credentials（.env.example 不算） | **中途**当场提醒「密钥别进仓库，先看看 .gitignore」——和危险命令一样是少数可以在中途出声的安全提醒，只提醒不拦截 |
| 批准疲劳 | 被问「要不要批准」问到麻木 | 10 分钟里批准请求 ≥6 次 | 不当场说，只给挫败度 +8（累积到线才在边界安慰） |
| 好的流程：先计划 | 先 plan 再动手 | 用过 plan 模式（90 分钟内）+ 清单（≥3 项）全划掉 | 收工那句换成「先计划再动手，清单全划掉，有条理」（顶替） |

没做的（没有可靠信号）：「删测试让它变绿」「编造 API」——要读 diff 内容才能判断，而我们只拿得到命令和退出码。
